# 修正記録：2026-11-27 請求締関連（登録側・第1弾）

2027 年消費税改正（軽減税率 8%→1%、2027-04-01〜2029-03-31）への対応。
今回は「請求締に関連する処理の、データを登録・生成・更新する側」のみを修正した。参照・照会・表示のみの側（帳票、照会画面、Dao の算出 select 等）と、受注・売上計上・取込の各処理は今回の対象外（別バッチで対応）。

## 共通方針

- 集計単位を「税区分」から「税区分＋税率」に変更する。軽減＝税区分 4＋6＋7。
- 新固定区分：6＝8%固定、7＝1%固定。税区分 '5' は子明細専用のまま。
- 新旧の判定は売上日ベース：適用税率が締日時点の税区分4 税率と一致すれば新枠、直前税率と一致すれば旧枠。一般（区分1、10%）の旧枠は当面 0 固定。
- 税率の数値はコードに直書きせず、税率マスタ S02M091T から取得する。
- S07T001T／S07T002T の旧枠列名は仮置：OLDKEIGENZEINUKIURIKIN、OLDKEIGENSHOHITAXKIN、OLDIPPANZEINUKIURIKIN、OLDIPPANSHOHITAXKIN。正式列名が決まったら一括置換する。列追加の DDL が全ての前提。
- 税額表示行 099903／099904 の商品マスタ税区分は「族」で登録する（099903＝'1'、099904＝'4'）。新旧の区別は税区分ではなく計算基準日で持つ。
- 本フォルダのファイルは GitHub 表示用に UTF-8 化したもの。実コードは CP932／CRLF（変換は可逆）。

### D1502B01B.SQL（請求締処理）
- 処理：SetSummaryValue（集計）、SeikyuFixProcess（通常締め）、SeikyuFixProcessOyako とその呼び出し側集計（親子）、InsertS06T001T/002TSeikyuFix（黒伝票生成）、InsertS07T001T（枠登録）、UpdateS07W006T（ワーク加算）、SetS07T001TRecord（初期化）。
- 変更：
  1. SetSummaryValue の税額集計 SELECT：S02M091T を売上日（伝票ヘッダ URIDD）で結合して行税率を求め、締日時点の税区分4 税率と同率の分を新枠（N8PER＊）、異なる分を旧枠（OLDKEIGEN＊）に分けて SUM する。MEISAITAXKIN の除外リストに '099903'/'099904' を追加。
  2. 再計算：新枠は従来通り締日税率。旧枠は税区分4 の直前期間の日付で SyohizeiKeisan 再計算する処理を追加。親子側は呼び出し元の請求先単位集計でも新旧を分割し、旧枠税額を直前期間税率で算出して新引数 iOldkeigenshohitaxkin で渡す。
  3. 黒伝票生成：InsertS06T002TSeikyuFix に 099903（明細番号3）／099904（明細番号4）の生成ブロックを既存ブロックの写しで追加。ヘッダ税額・枠合計（今回消費税額）・ワーク加算の各合算式に旧枠税額を加算。
  4. 枠登録：InsertS07T001T の列と値に旧枠 4 列を追加。初期化・クリア箇所にも旧枠の 0 初期化を追加。
- 留意点：①振り分けは「同率＝新／別率＝旧」の二分。税率マスタに行税率が無い明細は旧枠側に寄る。「同率でも直前でもない税率」をエラーにする仕様は未確定のため未実装。②代引き（回収方法区分 '7'）は従来通り再計算と黒伝票生成を行わない（旧枠も明細 SUM のまま）。③締め解除側は原伝票の複写・キー単位処理で 09990x を列挙していないため不変更で整合する。
