# 修正記録：2026-11-27 請求締関連（登録側・第1弾）

2027 年消費税改正（軽減税率 8%→1%、2027-04-01〜2029-03-31）への対応。
今回は「請求締に関連する処理の、データを登録・生成・更新する側」のみを修正した。参照・照会・表示のみの側（帳票、照会画面、Dao の算出 select 等）と、受注・売上計上・取込の各処理は今回の対象外（別バッチで対応）。

## 共通方針

- 集計単位を「税区分」から「税区分＋税率」に変更する。軽減＝税区分 4＋6＋7。
- 新固定区分：6＝8%固定、7＝1%固定。税区分 '5' は子明細専用のまま。
- 新旧の判定は売上日ベース：適用税率が締日時点の税区分4 税率と一致すれば新枠、直前税率と一致すれば旧枠。一般（区分1、10%）の旧枠は当面 0 固定。
- 税率の数値はコードに直書きせず、税率マスタ S02M091T から取得する。
- S07T001T／S07T002T の旧枠列名は仮置：OLDKEIGENZEINUKIURIKIN、OLDKEIGENSHOHITAXKIN、OLDIPPANZEINUKIURIKIN、OLDIPPANSHOHITAXKIN。正式列名が決まったら一括置換する。列追加の DDL が全ての前提。
- 税額表示行 099903／099904 の商品マスタ税区分は「族」で登録する（099903＝'1'、099904＝'4'）。新旧の区別は税区分ではなく計算基準日で持つ。
- 本フォルダのファイルは GitHub 表示用に UTF-8 化したもの。実コードは CP932／CRLF（変換は可逆）。

## 追記（2026-11-27 同日・修正2：列配置／命名標準／カナ表記＋第三者チェック）

ユーザー指摘を受けて SQL 4 件（01/02/04/05）を修正し、提出前に作者でない第三者による独立レビューを実施した（今後も提出前チェックを必須とする）。

### 01/02（S07 DDL）：新列を現行枠列の直後に配置
- ALTER TABLE ADD は末尾追加しかできないため、ADD の後に「枠列より後ろの全列（S07T001T は 69 列、S07T002T は 55 列）を INVISIBLE 化し、元の順序で VISIBLE に戻す」組み替え節を追加。新列 4 件が N10PERSHOHITAXKIN の直後に並ぶ。
- テーブル再作成（データ移行を伴う再構築）は制約・索引・権限・シノニム等の再現漏れリスクが高いため採用しない。前提は Oracle 12c 以降（11g では組み替え不可、その場合は ADD のみ＝末尾配置でも機能は同一）。INVISIBLE の間は対象列が SELECT * に現れないため、組み替え節は業務停止時間帯に PAUSE なしで一括実行する。中断した場合は VISIBLE 化の節だけを再実行すれば復旧できる。以上は SQL 冒頭にも明記した。列の表示順は業務 SQL（すべて列名指定）に機能影響しない。

### 04/05：名称の標準を「複写元からの派生」に統一
- 標準（1 本化）：新行の名称は字面値を直接書かず、複写元の行の値から派生させる（複写元の名称に「（直前）」を付加）。
- 04 の小分類名称は字面値（'消費税（直前）'、'軽減消費税（直前）'）だったため、`SCTGRYNM || '（直前）'` へ変更し 05 と揃えた（結果として得られる名称は従来と同じ）。

### 05：カナ項目は複写元の表記に合わせる
- 複写元のカナは AP基本コードにより半角（001/002：ｼｮｳﾋｾﾞｲ）と全角（048：ショウヒゼイ）が混在する。カナ項目への付加を、項目ごとに複写元の値で判定し、半角なら '(ﾁｮｸｾﾞﾝ)'、全角なら '（チョクゼン）' に変更した（従来は漢字の「（直前）」を一律付加）。名称・略称は複写元が漢字表記のため「（直前）」のまま。
